1. Install pprl

Install uv, then pprl 3.0.0rc1:

uv tool install https://github.com/TuftsCTSI/pprl/releases/download/v3.0.0rc1/pprl-3.0.0rc1-py3-none-any.whl

Open a new terminal, and run pprl: it lists its commands. If a step fails, or your computer restricts what you can install, write to Jo Example (jo@example.org).

2. Create your workspace

Your workspace is a new, empty folder you create, such as example-project-merge: somewhere your organization has approved for clinical data, on an encrypted drive, where files can be deleted permanently. Keep it out of search indexing, cloud sync and backups. You receive your bundle, merge.pprl, from Jo Example, over a secure channel. Save it, and any of the files in step 3 you have received, in the folder, open a terminal there, and run:

pprl init

pprl reads your role from the bundle and shows it back, makes the folder your workspace, and lists the files it created. Any other files stay as they are. Open a terminal in your workspace for every step below.

Every file in this folder is deleted at the end of the project, so keep nothing else here, such as your notes.

Open no file in your workspace, not even to look: an editor or your computer itself can leave copies of a file elsewhere on the disk, such as backup files or a search index, which pprl cannot delete. To see what a file holds, run pprl inspect on it.

If you ever receive a bundle other than your own, do not open it: delete it, and tell Jo Example.

3. Merge the sites' tables

The linkage agent sends you the linkage file, linkages.pprl, and each site participant sends you the site's tables, over a secure channel. The linkage file is expected around 14:00 on Monday 16 November 2026 and the tables around 15:00 on Monday 16 November 2026. Save them in your workspace folder, if you have not already, under the names they have:

  • site_a.tables.pprl, from site_a
  • site_b.tables.pprl, from site_b

Never open or rename them: pprl refuses a file that was opened and saved. Then run:

pprl merge

pprl checks that every file is from this project's set of bundles, and that each site's tables and hashes came from the same run at that site, then merges each table by the project's rules. It writes outbox/host/merged/, one CSV file for each table:

  • outbox/host/merged/scores.csv: the columns person_id and score; one row for each person_id.

The column person_id holds each person's new id, the same in every table: a random number, drawn anew each time, that no site's ids can be traced from.

5. At the end of the project

Do not run pprl destroy until Jo Example tells you that the project's transfers are complete. This is planned for shortly before 17:00 on Monday 16 November 2026. Then delete any copy you shared of the merged dataset, and every other copy of the files you received, wherever they were shared, such as in your downloads folder. Then, in your workspace, run:

pprl destroy

pprl lists every file in your workspace, asks you to type "yes", and deletes them permanently. It leaves the folder, with only your receipt, outbox/coordinator/merge.receipt_<date>.txt: send it to Jo Example over a secure channel. The receipt holds your workspace's merge.log, and no patient details or secret. You may then delete the folder.

pprl destroy cannot delete copies kept by your storage (recycle bins, version history, retention policies and backups; OneDrive keeps deleted files for up to 93 days), so follow these up. Nor can it delete files you sent on, such as hashes at the linkage agent: each recipient destroys the copies received, and confirms that. Your drive's encryption protects data left on the drive after deletion.
