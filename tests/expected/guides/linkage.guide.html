1. Install pprl

Install uv, then pprl 3.0.0rc1:

uv tool install https://github.com/TuftsCTSI/pprl/releases/download/v3.0.0rc1/pprl-3.0.0rc1-py3-none-any.whl

Open a new terminal, and run pprl: it lists its commands. If a step fails, or your computer restricts what you can install, write to Jo Example (jo@example.org).

2. Create your workspace

Your workspace is a new, empty folder you create, such as example-project-linkage: somewhere your organization has approved for the project's files, on an encrypted drive, where files can be deleted permanently. Keep it out of search indexing, cloud sync and backups. You receive your bundle, linkage.pprl, from Jo Example, over a secure channel. You can create your workspace at any time before linking, such as once the sites' hash files arrive (step 3). Save the bundle, and any hash files you have, in the folder, open a terminal there, and run:

pprl init

pprl reads your role from the bundle and shows it back, makes the folder your workspace, and lists the files it created. Any hash files stay as they are. Open a terminal in your workspace for every step below.

Every file in this folder is deleted at the end of the project, so keep nothing else here, such as your notes.

Open no file in your workspace, not even to look: an editor or your computer itself can leave copies of a file elsewhere on the disk, such as backup files or a search index, which pprl cannot delete. To see what a file holds, run pprl inspect on it.

If you ever receive a file meant for a site participant, such as a site's bundle, secret file or private key, do not open it: delete it, and tell Jo Example. The secret is what you must never have.

3. Link the sites' hashes

Each site participant sends you the site's hash file, over a secure channel, expected around 12:00 on Monday 16 November 2026. Save each in your workspace folder, if you have not already, under the name it has:

  • site_a.hashes.pprl, from site_a
  • site_b.hashes.pprl, from site_b

Never open or rename them: pprl refuses a file that was opened and saved. Then run:

pprl link

pprl checks that it has every site's file, from this project's set of bundles, and links them. It writes outbox/merge/linkages.pprl, and says how many records it linked between each pair of sites. Read its warnings, and do what each says.

It also writes outbox/coordinator/linkage_report.pprl, the linkage report: what pprl showed you about the linkage's quality, as counts only, with no record and no hash. To see what it holds, run pprl inspect on it.

4. Send the linkage file and the linkage report

Send each file in your workspace's outbox/ folder, as it is, over a secure channel. This is planned for around 14:00 on Monday 16 November 2026:

  • outbox/merge/linkages.pprl, to the merge agent, Max Example (max@example.org);
  • outbox/coordinator/linkage_report.pprl, to the coordinator, Jo Example (jo@example.org).

Never send anything else from your workspace, and above all never send the hashes on. Then wait: Jo Example judges from the report whether the linkage is plausible, and tells you what to do next. Keep your workspace until then.

5. Delete the hashes and destroy your workspace

Do not run pprl destroy until Jo Example tells you the linkage is plausible. You should hear soon after you send the report: the other roles' go-ahead waits for your receipt, and is planned for around 14:30 on Monday 16 November 2026. Then, before any table arrives, first check that the merge agent has the linkage file, at the same size as outbox/merge/linkages.pprl, as what you run below deletes your only other copy. Then delete every copy of the files you received, the hashes above all, wherever they were shared, such as in your downloads folder or in messages you sent or received, emptying deleted items, and any copy of the linkage file and the linkage report you shared. Then, in your workspace, run:

pprl destroy

pprl lists every file in your workspace, asks you to type "yes", and deletes them permanently. It leaves the folder, with only your receipt, outbox/coordinator/linkage.receipt_<date>.txt: send it to Jo Example over a secure channel. Jo Example gives the site participants and the merge agent the go-ahead only after receiving it. The receipt holds your workspace's linkage.log, and no patient details or secret. You may then delete the folder.

pprl destroy cannot delete copies kept by your storage (recycle bins, version history, retention policies and backups; OneDrive keeps deleted files for up to 93 days), so follow these up. Nor can it delete files you sent on, such as hashes at the linkage agent: each recipient destroys the copies received, and confirms that. Your drive's encryption protects data left on the drive after deletion.
